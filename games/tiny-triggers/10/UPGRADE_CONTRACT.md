# V6 earlier-scene upgrade contract

Read SCENE_CONTRACT.md for the custom api and real-input test interface. Each scene is an individual assignment with its own file/test. Workers process their assigned queue strictly one scene at a time, finishing verification before the next. Three workers maximum. Do not edit shared files, original versions, or other workers' scene files. Do not commit or push.

For each scene use `TinyV6.register(INDEX, {id, title, description, hint, verdict, create(api) {...}})` in `upgrades/<id>.js`. Preserve the identity and title from UPGRADE_MANIFEST.json. No `TinyV5.register` (that appends scenes). The register adapter replaces the scene in place and uses the existing v5 custom-scene API. Write test to `tests/tiny-triggers-v6/upgrades/<id>.cjs`. Run `node tests/tiny-triggers-v6/upgrade.cjs <id>` and `MOBILE=1 node tests/tiny-triggers-v6/upgrade.cjs <id>`. Use `io.shot('during')` for a meaningful middle state. Inspect your start/during/finish screenshots in `/tmp/tt6-upgrades` with view_image; fix ugly/unrecognizable results before acceptance. A passing state flag is not sufficient.

Goal: bring each earlier scene to the authored v5 quality. New scene-specific illustrations and meaningful, smoothly animated physical transformations are required, NOT a uniform glow or texture overlay on the old props. No generic title-card screens. Draw recognizable large objects with materials, contours, lighting/shadows, layered depth and visible action aftermath. Preserve each exact underlying harmless crime and all essential narrative beats. Use generous mouse/touch targets, intuitive directly manipulated tools/objects, reversible invalid drops, pointer-cancel handling. No automatic completion without the required gesture(s). Do not replace dragging with unrelated buttons. End result remains visible after done. Retain or improve existing mechanics (e.g. milk THEN cereal, no intermediate parking for burger bun, banana long peel from bottom, paper hangs front/back not sideways). Use short sparse text only as secondary feedback.

Self-contained scene-local state. Animation in update(dt), not real timers. Helpers via api or Canvas ctx; no new network assets/dependencies. Can use small drawing helpers internal to your file. Code-native canvas is appropriate; image generation unnecessary. Keep the original dark calm game aesthetic.

For each scene, send parent a concise completion message containing id/index, concrete visual+motion improvements, mouse/touch result, screenshot paths. Then proceed to the next individual item in your queue. If a scene is blocked, fix it before moving on; notify parent. Keep per-scene notes in `tests/tiny-triggers-v6/upgrades/<id>.md` with changes/gestures/results. Do not claim more verification than performed.
